# План архитектурного улучшения проекта

Цель: превратить текущий монолитный HTML-файл в проект, где можно безопасно менять интерфейс, добавлять уровни, новые режимы игры, звук, таблицу лидеров и тесты без риска сломать весь сценарий.

## 1. Текущее состояние

Сейчас приложение собрано в одном файле `Учим ноты_финальная.html`:

- HTML-разметка, CSS, встроенный шрифт и JavaScript находятся вместе.
- Правила уровней, генерация нот, отрисовка нотного стана, клавиатура, таймеры, таблица лидеров и Firebase живут в одном модуле.
- Уровни описаны частично как конфиг, но логика их построения зашита в функции `buildEasiestPool`, `buildEasyPool`, `buildMediumPool`, `buildHardPool`.
- Внешний Firebase импортируется сразу при старте модуля, поэтому офлайн-режим зависит от доступности CDN.
- Нет автоматической проверки, что диапазоны нот, MIDI-значения, уровни и UI-селекторы остались рабочими после правок.

Главный риск: любая небольшая правка может случайно повлиять на несвязанную часть игры, потому что границы между подсистемами не выражены в структуре проекта.

## 3. Разделение ответственности

### `game/`

Содержит чистую игровую логику без DOM, Canvas, Firebase и `localStorage`.

- `noteModel.js`: `diatonicIndex`, `midiValue`, `buildNote`, русские названия нот, обозначения октав.
- `notePools.js`: функции построения диапазонов, случайное перемешивание, фильтры по MIDI.
- `levels.js`: декларативное описание уровней.
- `modes.js`: будущие варианты игры, например "угадай ноту", "нажми клавишу по названию", "слуховой режим".
- `gameEngine.js`: текущий вопрос, очередь вопросов, обработка ответа, переход к следующему вопросу.
- `scoring.js`: правила начисления очков, штрафов, серий правильных ответов.

Правило: если функцию можно протестировать без браузера, она должна жить в `game/`.

### `ui/`

Содержит только отображение и обработку пользовательских действий.

- `dom.js`: безопасный сбор всех DOM-элементов и проверка обязательных селекторов.
- `screens.js`: переключение экранов.
- `staffCanvas.js`: отрисовка нотного стана и ноты по готовой модели `Note`.
- `keyboard.js`: создание клавиатуры и подсветка правильных/неправильных клавиш.
- `leadersView.js`: отрисовка таблиц лидеров.
- `modals.js`: результат, повтор игры, выход.

Правило: UI получает готовое состояние и вызывает команды приложения, но не знает, как строятся уровни.

### `services/`

Содержит внешние зависимости и побочные эффекты.

- `localLeaders.js`: чтение/запись локальных результатов.
- `firebaseLeaders.js`: облачная таблица лидеров.
- `leaderRepository.js`: единый интерфейс, который выбирает Firebase или локальный режим.
- `sound.js`: звук пианино, будущие аудио-настройки.

Правило: Firebase не должен импортироваться в основной поток, если конфиг не заполнен. Лучше использовать динамический импорт внутри `firebaseLeaders.js`.

## 4. Декларативные уровни

Чтобы добавлять уровни без изменения движка, уровни стоит описывать данными:

```js
export const levels = {
  easiest: {
    title: 'Первый',
    hints: true,
    mode: 'press-key-by-staff-note',
    clefs: ['treble'],
    range: { from: ['B', 3], to: ['F', 5] },
    accidentals: ['natural'],
  },
  hard: {
    title: 'Четвёртый',
    hints: false,
    mode: 'press-key-by-staff-note',
    clefs: ['bass', 'treble'],
    ranges: {
      treble: { from: ['E', 4], to: ['F', 5] },
      bass: { from: ['G', 2], to: ['A', 3] },
    },
    accidentals: ['sharp', 'flat', 'natural-sign'],
    alternateClefs: true,
  },
};
```

После этого новый уровень добавляется как новая запись в `levels.js`, а не как новая ветка в коде приложения.

## 5. Новые режимы игры

Режимы лучше проектировать как плагины с одинаковым интерфейсом:

```js
export const modes = {
  'press-key-by-staff-note': {
    createQuestion,
    checkAnswer,
    renderQuestion,
  },
  'choose-note-name-by-staff-note': {
    createQuestion,
    checkAnswer,
    renderQuestion,
  },
};
```

Тогда уровень выбирает `mode`, а приложение не переписывается под каждый новый сценарий.

Примеры будущих режимов:

- Нота на стане -> нажать клавишу.
- Нота на стане -> выбрать название ноты.
- Название ноты -> нажать клавишу.
- Звук -> нажать клавишу.
- Интервалы -> выбрать расстояние между нотами.
- Аккорды -> определить тип аккорда.

## 6. Безопасная работа с таблицей лидеров

Нужен единый интерфейс:

```js
export function createLeaderRepository(config) {
  if (config.firebaseEnabled) return createFirebaseLeaderRepository(config.firebase);
  return createLocalLeaderRepository();
}
```

Приложение должно работать одинаково:

```js
await leaders.save(result);
const top = await leaders.getTop({ level: 'easy', limit: 5 });
```

Так Firebase можно чинить, отключать или заменять без изменений в игровом движке и UI.

## 7. Тесты, которые дадут уверенность

Минимальный набор тестов:

- `noteModel.test.js`: MIDI для `C4`, `A4`, диезов, бемолей, натуральных знаков.
- `notePools.test.js`: диапазоны не выходят за клавиатуру `45..88`, нет пустых пулов, сложный уровень чередует ключи.
- `levels.test.js`: каждый уровень имеет валидный `mode`, диапазон, ключи и accidentals.
- `gameEngine.test.js`: правильный ответ увеличивает счет, неправильный не увеличивает, очередь пополняется.
- `leaderRepository.test.js`: локальные результаты сортируются по счету и дате.

Для старта достаточно `vitest`. Эти тесты не требуют браузера и будут быстрыми.

## 8. Поэтапная миграция

### Этап 1. Подготовка без изменения поведения

- Переименовать рабочий HTML в `index.html` или оставить старое имя, но зафиксировать его как входную точку.
- Вынести CSS в `src/styles/*.css`.
- Вынести встроенный JS в `src/main.js`.
- Подключить `main.js` как `<script type="module" src="./src/main.js"></script>`.
- Проверить, что игра визуально работает так же.

### Этап 2. Вынести чистую музыкальную логику

- Создать `src/game/noteModel.js`.
- Перенести туда `semitones`, `letterIndex`, `diatonicIndex`, `midiValue`, `buildNote`, `buildRuLabel`.
- Добавить первые unit-тесты.
- Убедиться, что UI только импортирует готовые функции.

### Этап 3. Вынести уровни и генерацию пулов

- Создать `src/game/levels.js` и `src/game/notePools.js`.
- Перевести уровни в декларативные конфиги.
- Сделать одну универсальную функцию `buildPoolForLevel(levelConfig)`.
- Покрыть тестами все существующие уровни.

### Этап 4. Вынести движок игры

- Создать `src/game/gameEngine.js`.
- Перенести туда состояние раунда: текущая нота, счет, очередь, проверка ответа.
- UI должен только подписываться на изменения и вызывать `answer(midi)`.

### Этап 5. Вынести UI-слой

- Создать модули `staffCanvas.js`, `keyboard.js`, `leadersView.js`, `screens.js`.
- Запретить этим модулям напрямую менять правила игры.
- Ввести явные функции вроде `renderGame(state)` и `renderLeaders(leaders)`.

### Этап 6. Изолировать внешние сервисы

- Вынести `localStorage` в `localLeaders.js`.
- Вынести Firebase в `firebaseLeaders.js`.
- Перейти на динамический импорт Firebase только при реальном конфиге.
- Оставить локальный режим как гарантированный fallback.

### Этап 7. Добавить новые возможности уже на новой базе

- Добавить звук через `services/sound.js`.
- Добавить новый режим через `modes.js`.
- Добавить новый уровень только через `levels.js`.
- Проверять изменения тестами перед ручной проверкой в браузере.

## 9. Правила для будущих правок

- Новая музыкальная логика сначала добавляется в `game/`, потом подключается к UI.
- Новый уровень добавляется конфигом в `levels.js`; если для него нужна новая механика, сначала добавляется режим в `modes.js`.
- UI не должен читать или писать `localStorage` напрямую.
- Canvas не должен сам выбирать следующую ноту.
- Firebase не должен быть обязательным для запуска игры.
- Любая новая функция, которая не зависит от DOM, должна иметь unit-тест.
- Большие визуальные изменения лучше делать после тестов игровой логики, чтобы легче отличать ошибку интерфейса от ошибки правил.

## 10. Критерий готовности архитектуры

Архитектура станет достаточно устойчивой, когда будут выполнены условия:

- Можно добавить пятый уровень одной записью в `levels.js`.
- Можно добавить новый режим без изменения существующих режимов.
- Можно отключить Firebase, и игра продолжит запускаться.
- Можно поменять внешний вид клавиатуры без правок генерации нот.
- Unit-тесты проверяют все текущие уровни и базовые MIDI-расчеты.
- Главный файл запуска только связывает модули, а не содержит всю бизнес-логику.
